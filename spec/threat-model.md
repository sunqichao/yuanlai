# 威胁模型与已知局限

## 1. 要保护的资产

| 资产 | 期望的性质 |
|---|---|
| 课程登记记录 | 不可篡改；时间顺序可信 |
| 作者身份秘密 | 不泄露、不可被冒用 |
| 额度规则 | 不能凭空产生，不能无限续命，不能被集中囤积 |
| 节点可用性 | 不会被畸形输入击垮 |

## 2. 威胁与对策

| 编号 | 威胁 | 对策 | 残余风险 |
|---|---|---|---|
| T01 | **历史重写**：自建链的算力集中，控制者可以重新计算整条链 | 见证节点；每天在链外公开发布检查点（最新区块 ID）；重要登记做公证 | **高**。这是自建链的根本局限，必须靠链外检查点缓解 |
| T02 | 算力攻击导致重组 | 最大累计工作量规则；undo 回滚 | 建议登记后等待至少 60 个确认再作为证据 |
| T03 | 时间戳操纵 | 中位时间（BLK-07）、防时间扭曲（BLK-08）、未来时间限制（BLK-ACCEPT-01） | 单个区块的时间戳仍有约 ±10 分钟的误差；证据应以区块高度为主 |
| T04 | 额度续命（互转、开始后取消、等待自动取消） | 转账损耗、转账次数上限、防回转、取消费和次数限制、续期次数上限；`hops` 与 `renewals` 永不重置 | 低。最长存活时间有上限，见 rationale.md |
| T05 | 通过会话冻结额度 | 锁定上限、单一会话、会话超时 | 最多冻结约 7 天，且需要真实的课程声明 |
| T06 | 垃圾交易 | 零成本交易必须由已登记身份的地址发起；每个区块中每个地址的交易数有上限；各类长度上限；交易池策略 | 中。P5 网络模式尚无 peer 配额和请求速率限制 |
| T07 | **抢先登记**：攻击者从交易池中看到 `AppendFiles` 中的文件哈希，抢先完成登记 | 攻击者只有哈希、没有原文件，在争议中无法出示内容 | 中。后续可以通过 YIP 引入"先提交承诺、再公开"的两阶段登记 |
| T08 | 身份信息被暴力枚举 | 身份承诺中包含高熵的 `secret` 和 `salt` | 取决于用户是否妥善保管 |
| T09 | 证明重放或挪用 | `challenge` 由验证方生成；`nullifier` 只能使用一次；证明绑定 `course_root` | 低 |
| T10 | 私钥泄露 | 保留 `RotateKey`，后续通过 YIP 启用 | 启用前，泄露的私钥无法作废 |
| T11 | 抢注常见文件，阻止他人登记 | 不强制内容哈希全局唯一 | 无 |
| T12 | 零知识电路约束不足，导致可以伪造证明 | MockProver 正反例测试；外部审计 | 审计前视为中风险 |
| T13 | 跨平台共识分歧 | 共识层禁止浮点、禁止 `HashMap`、全部使用 checked 算术；测试向量；三平台 CI | 低 |
| T14 | 供应链攻击 | 依赖最少化；`cargo-deny`；锁定 `Cargo.lock`；可复现构建 | 中 |
| T15 | 额度在链下被有偿交易 | 24 小时有效期、转账损耗、禁止转账次数超限、用户协议禁止 | 技术上无法完全杜绝 |
| T16 | 隐私泄露：标题和文件路径公开在链上 | 客户端应当提示用户使用中性的标题和路径 | 由用户自行决定 |
| T17 | 矿工拒绝打包某人的交易 | 作者可以自己挖矿打包 | 低 |
| T18 | 畸形帧、慢速或恶意 P2P peer 消耗资源 | 帧长度先限后分配；握手校验 chain ID/version/nonce；区块和 headers 全量验证；连接读写超时；入站 peer 并发上限为 8 | 高。当前无加密、peer 身份认证、IP 配额或请求速率限制；网络模式为实验功能，不应暴露到不可信网络 |
| T19 | 未认证 HTTP 查询导致链状态泄露或资源消耗 | 仅 GET、请求行与 headers 限长、连接读写超时、文件未变化时复用已校验快照 | 中。API 无认证、无 TLS、无速率限制；应只绑定 loopback，不应暴露到不可信网络 |

## 3. 已知局限

1. **只能证明时间在先，不能证明原创**。如果别人在你之前拿到了内容并登记，链上记录会对你不利。务必在课程公开之前登记。
2. **无法识别修改过的内容**。转码、剪辑、加水印都会改变文件哈希，此时要依靠原始母版和更早的登记时间举证。
3. **自建链的公信力有限**。见 T01，必须配合链外检查点、公证和国家版权登记。
4. **秘密值就是身份**。私钥、`secret`、`salt` 一旦泄露，身份就可能被冒用；一旦丢失，就无法再证明身份。
5. **只读 API 不是安全边界**。HTTP 总览接口会公开本地节点的网络和链状态；它不提供认证或传输加密。默认应绑定 `127.0.0.1`，需要远程查看时应在可信网络中自行配置受控反向代理。
