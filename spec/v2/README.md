# 原链 V2 协议草案

- 版本：草案 0.1
- 日期：2026-10-02
- 状态：N2 进行中，**非规范、未冻结、不得用于生产或跨实现兼容承诺**
- 目标：定义无 PoW、无代币的文件指纹登记账本；旧协议见本目录以外的 legacy 规格
- 相关：[产品方案](../../docs/new-product-proposal.md)、[威胁模型](../../docs/new-threat-model.md)、[项目跟踪](../../docs/project-tracking.md)

## 1. 设计边界

V2 与旧版 PoW/Credit 链完全分离：采用新的 `chain_id`、创世配置、数据目录、区块和网络消息版本。V2 不解析旧版区块，不导入旧版课程/身份/Credit 记录。

产品核心已修订为**本机优先**：单机离线创建、保存、导出和核验签名的文件指纹声明，不要求验证者、账号、互联网或公共网络。本文仅描述未来可选共享网络的记录格式/同步确认接口，不是本机核心功能规范。本机记录与公共同步回执必须分开保存和展示；同步失败不得阻止本机使用。CometBFT + Rust ABCI++ 仍只是共享网络候选：单验证者交易/查询 PoC 已通过，四验证者测试因 SecretConnection 认证失败而没有 peer 或共同区块，原因尚未定位，因此不得视为已选生产依赖。

本机签名证明的是对应密钥签过该指纹/声明；本机时间不是独立可信时间。可选共享网络确认可以证明该网络在确认时收到记录，不能证明最早创作人、现实身份、著作权归属或文件内容合法性。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 文件指纹 `fingerprint` | 原始文件字节的 SHA-256 摘要，32 字节；不做 MIME 转换、解压或文本规范化 |
| 登记声明 `record` | 提交者签署的摘要、作品名、声明人文本和防重放字段 |
| 登记 ID `record_id` | 对完整规范化登记声明及其签名做域分离哈希得到的标识 |
| 区块 | 按高度连接、包含一批有效登记声明并由验证者共识确认的账本单元 |
| 最终确认 | 按待选 BFT 算法获得法定人数提交证明后，节点不得静默回滚的状态 |
| 验证者集合 | 版本化公钥列表及权重/规则；MVP 暂不引入权重，名单治理待决 |

## 3. 文件指纹与登记声明

### 3.1 文件指纹

MVP 算法标识暂定 `1 = SHA-256`，计算输入是用户选择文件的精确字节序列：

```text
fingerprint = SHA256(file_bytes)
```

不解压 ZIP，不解析 DOCX/PDF，不去除 PDF metadata，也不对文本做 Unicode 规范化。任何字节变化都会得到另一个输入序列。浏览器端对大文件应使用经测试的增量哈希实现，不能把整个文件无上限载入内存；算法必须与 Rust 全节点通过共同测试向量。

摘要编码显示为 64 位小写十六进制。链上编码存原始 32 字节，不存大小写可变的十六进制字符串。

### 3.2 登记声明字段

以下字段构成签名消息。表中 UTF-8 字段先做 Unicode NFC；需限制最大编码字节数，具体上限待 N1 性能/产品确认后冻结。

| 字段 | 类型 | 是否签名 | 说明 |
|---|---|---:|---|
| `protocol_version` | 固定整数 | 是 | 防止跨协议解释 |
| `chain_id` | 固定长度字节串/规范 ID | 是 | 防止跨网络重放 |
| `hash_algorithm` | 枚举 | 是 | MVP 值为 SHA-256 |
| `fingerprint` | 32 字节 | 是 | 原始文件字节摘要 |
| `file_size` | 无符号整数 | 是 | 原始文件字节数；不能代替摘要验证 |
| `work_title` | NFC UTF-8 字符串 | 是 | 用户填写的作品名称，是声明内容 |
| `claimant_name` | NFC UTF-8 字符串 | 是 | 用户填写的权利人/声明人文字，不代表实名核验 |
| `display_filename` | 可选 NFC UTF-8 字符串 | 是 | 默认建议不写入链，避免不必要公开；如启用则永久公开 |
| `signer_public_key` | 32 字节 Ed25519 公钥 | 是/消息域 | 标识签名密钥，不等同自然人身份 |
| `nonce` | 固定长度随机字节 | 是 | 防止同字段声明被签名/记录重放；生成规则和长度待冻结 |
| `signature` | Ed25519 签名 | N/A | 对下述域分离消息签名 |

签名消息草案：

```text
signing_bytes = "YuanLai/registry/v2/record" ||
                canonical(protocol_version, chain_id, hash_algorithm,
                          fingerprint, file_size, work_title,
                          claimant_name, display_filename, signer_public_key,
                          nonce)
signature = Ed25519.Sign(signer_secret, signing_bytes)
```

实现必须使用单一确定性编码；禁止直接拼接可变长字段而不编码长度。最终应在 Rust 和浏览器实现之间共享十六进制签名向量，至少覆盖非 ASCII 名称、空/大字段边界、字段替换、跨 chain ID 和 nonce 重放。

### 3.3 登记 ID 与重复登记

登记 ID 草案：

```text
record_id = SHA256("YuanLai/registry/v2/record-id" || canonical(record_body, signature))
```

同一个文件指纹可以有多条登记记录，例如不同声明人、作品名或时间；指纹不是用户账户 ID，也不做全网唯一约束。客户端随机 nonce 使同一声明的重提行为可区分；客户端可以先查询相同签名消息是否已收录，但共识不把相同指纹视为重复垃圾自动丢弃。

## 4. 区块与确认数据

区块头字段草案：

| 字段 | 草案用途 |
|---|---|
| `protocol_version` | 解析区块版本 |
| `chain_id` | 网络隔离 |
| `height` | 从创世块递增的高度 |
| `parent_block_id` | 前一区块标识 |
| `record_merkle_root` | 本区块登记声明的 Merkle 根；空块规则待定 |
| `validator_set_id` | 当前验证者配置的内容哈希/版本 |
| `block_time` | 经共识提交的区块时间观察；可信误差边界待定 |
| `proposer_id` | 该轮提议者在当前集合中的索引或公钥标识 |

`block_id` 由协议域分离哈希和区块头规范编码产生。确认数据必须绑定 `chain_id`、height、round/sequence、`block_id`、validator set version 和阶段/用途标签，避免把其他轮次或网络的签名拿来充当提交证明。验证者重复签名、公钥重复计数或验证者集合不匹配一律无效。

**共识算法尚未选定。** 不从“2f+1 个签名”推导完整安全性；法定人数、锁定规则、提议者轮换、视图切换、超时、冲突区块处理、最终性证明和集合升级必须来自明确指定且审查过的 BFT 协议/实现及版本。N2 ADR 完成前，本草案中的 block/QC 字段是接口候选，不是可执行共识规范。

候选调研与 PoC 验收门槛见 [ADR 0007](../../docs/adr/0007-v2-bft-engine-evaluation.md)。在候选实现确认之前，本节的 `2f+1` 只描述抽象容错方向，不定义任何 YuanLai 共识规则。

## 5. 时间语义

- 本机记录可显示系统生成的设备时间，但必须标为“本机时间”，不作为独立可信时间证明。
- 用户可离线完成登记；之后同步得到的网络接收/确认时间单独附加显示，不能倒推离线创作时间。
- 只有可选共享网络确认时间才显示网络 ID、高度、区块 ID 和验证者集合版本。
- 共享网络时间仍受验证者时钟/信任模型约束；没有外部可信时间锚时，不能宣称绝对准确的现实时间。
- 允许的前后偏差、时间来源、法定人数如何形成 block time 由 BFT 规范定义，禁止每个全节点基于本机墙上时钟对同一块做不同的共识有效性判断。

## 6. 验证与状态机

全节点按以下逻辑验证登记声明：

1. 解码必须完整、规范；拒绝超长字段、尾随字节、未知必需版本和无效 UTF-8/NFC。
2. `chain_id` 与节点配置匹配；算法 ID 被该协议版本允许。
3. 计算 `record_id`；校验公钥格式和签名覆盖的完整消息。
4. 验证声明被包含在区块 Merkle root；验证父块、高度、集合版本和区块 ID。
5. 按指定 BFT 协议验证最终确认凭证；没有最终确认凭证只能显示 `pending`，不可签发正式证书。
6. 本地验证文件时重新计算 SHA-256，与记录的算法 ID、字节长度和指纹比对；匹配只说明字节级一致。

无余额状态、UTXO、奖励、转账、手续费市场、mempool Credit 校验或挖矿 nonce。节点可按网络策略缓存待确认记录，但待确认交易不能伪装为最终链记录。

## 7. 同步、全量数据与内存限制

- 新节点启动时必须从可信配置的创世块和验证者集合版本开始验证，不因 peer 返回“已验证”标志而跳过本地校验。
- 默认目标是完整验证和保存全部登记记录。可依据可用内存调节下载并发数、批次大小和磁盘写入节奏；内存不足只能减速/暂停，不可默默跳过历史区块。
- 远端 peer 数据视为不可信输入；同步先验证 header/提交证明，再下载并校验包含记录。校验失败时保留最后一个有效高度并报告错误。
- 记录量很大后可以研究快照，但快照必须带可验证的状态根/检查点证明，并允许回补和核对历史；不能以近期块覆盖历史而仍宣称 full node。
- 是否支持裁剪节点、快照频率和数据保留策略待实现评估。MVP 不默认裁剪登记历史。

## 8. 错误分类与用户状态

| 状态 | 解释 | 是否可签发正式证书 |
|---|---|---:|
| `local_ready` | 浏览器完成本地哈希和签名预览，尚未广播 | 否 |
| `local_saved` | 已在本机持久保存并可离线导出/验证，未同步 | 可签发本机签名凭证；不得标成网络确认 |
| `submitted` | 节点接收请求，尚未进入最终区块 | 否 |
| `pending` | 已进入候选/等待共识 | 否 |
| `confirmed` | 最终确认凭证通过本节点验证 | 是 |
| `rejected` | 格式、签名、策略或额度外（新版无币）限制不通过 | 否 |
| `unknown` | 当前节点尚未同步到对应记录，或记录 ID 不存在 | 否 |

用户界面不得把 `submitted` 或 `pending` 写成“已上链”；本机保存记录应与共享网络确认分开展示。

## 9. 开放参数与冻结门槛

以下事项未决，任何值不得作为最终兼容承诺：

- 唯一正式 `chain_id`、创世配置和验证者集合如何签发/升级。
- BFT 算法、状态机版本、实现语言/依赖、法定人数与故障模型。
- Metadata 最大字节数、`nonce` 长度/生成、安全的签名 key storage。作品名与声明人明文上链的方向已确认；文件名默认不上链，完整 UI 确认文案待定。
- 文件最大字节数、空文件政策、`display_filename` 是否允许上链以及每条记录字节上限。
- `record_id`/Merkle 树的精确哈希域、奇数叶处理、空区块根、规范整数编码和测试向量。
- 区块时间来源、精度、最大时钟偏差与外部时间锚定策略。
- P2P handshake、消息编码、同步状态/快照格式、兼容与升级协商。
- Web API 上传请求形式、本地签名接口、速率限制、公开字段确认与隐私保留策略。

只有上述共识/编码/时间相关参数经 ADR 审查、形成跨实现测试向量并经过至少两种独立实现互验后，才可将本草案标为冻结并进入 N3/N4 对接实现。
