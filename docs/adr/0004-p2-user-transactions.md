# ADR 0004：P2 用户交易与身份

- 状态：已接受
- 日期：2026-09-28

## 决策

### 1. 现在就固定身份承诺所在的域

TX-ID-03 原本引用尚未编写的 06 章。既然已经选定 halo2，电路原生域就确定是 Pallas 基域，因此现在就把模数和编码（32 字节小端序，与 Pasta 库一致）写入规范。这样 P2 登记的身份承诺不会在 P4 时失效。

### 2. 签名消息是 32 字节摘要，发送方公钥必须有效

`sig_msg` 已经包含 chain_id 并做了域分离，对它签名即可。TX-SIG-01 同时要求发送方公钥满足 TX-CB-02 的有效性定义：否则同一个曲线点的非规范编码会被当作另一个地址，导致一把私钥控制两个地址。

### 3. 测试向量生成器自带 Ed25519 实现

Python 标准库没有 Ed25519。生成器按 RFC 8032 从零实现（约 60 行），运行前先断言 RFC 8032 测试向量 1。Rust 端（`ed25519-dalek`）必须与之逐字节一致，也就是两个独立实现互相印证。

### 4. 转账历史全量保留

TX-TRANSFER-05 和 TX-TRANSFER-07 只需要最近 1440 个区块的历史，但裁剪历史本身也是状态变更，需要自己的撤销记录。目前保留全部历史以保持简单；等状态规模确实成为问题时，再引入确定性裁剪（另写 ADR）。

### 5. 钱包侧的选输入逻辑放在共识 crate

`ChainState::select_inputs` 按 TX-IN-02 到 TX-IN-04 的规则选择输入，与共识校验放在同一处实现，避免钱包与共识对"合法输入"的理解出现偏差。
