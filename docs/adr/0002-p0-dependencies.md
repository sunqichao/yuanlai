# ADR 0002：P0 依赖与实现选择

- 状态：已接受
- 日期：2026-09-28

## 决策

### 1. 运行时依赖 `sha2`（RustCrypto，MIT OR Apache-2.0）

SHA-256 是协议的核心原语，自行实现得不偿失。RustCrypto 的 `sha2` 是 Rust 生态中使用最广泛、审查最充分的实现，本身没有 C 依赖。

### 2. 自行实现 `U256`，不引入大整数库

协议只需要比较、加、减、乘 `u64`、除以 `u64`、256 位除法这几种运算，约 200 行即可实现，而且全部代码可以审计。通用大整数库的代码量大得多，其中大部分功能用不上，却同样要被审计。

正确性由两层独立检验保证：
- 用 `num-bigint` 作为预言机，做属性测试（每种运算 2000 个随机样本，偏向边界值）；
- 用独立的 Python 实现生成测试向量（Python 整数无上限，天然是 256 位运算的参照）。

### 3. 测试与 JSON 依赖

| crate | 用途 | 许可证 |
|---|---|---|
| `proptest` | 属性测试 | MIT OR Apache-2.0 |
| `num-bigint` | `U256` 的测试预言机 | MIT OR Apache-2.0 |
| `hex` | 读取测试向量 | MIT OR Apache-2.0 |
| `serde_json` | 读取测试向量及只读 HTTP API 的 JSON 编码 | MIT OR Apache-2.0 |

除 `serde_json` 外，它们只出现在 `dev-dependencies` 中，不会进入发布的二进制文件。`serde_json` 只由 API crate 在运行时使用，不进入共识核心 crate。

### 4. 测试向量由独立的 Python 实现生成

`tools/testvectors/generate.py` 只使用 Python 标准库，按规范直接实现，不与 Rust 代码共享任何逻辑。两个独立实现得出相同结果，比"实现自己生成、自己校验"可信得多。CI 会用 `--check` 模式确认仓库中的测试向量与生成器一致。

### 5. 新增回归测试网（regtest）

主网难度下限约需 100 万次哈希才能出一个块，跨越多个难度调整周期的测试会非常慢。regtest 只放宽难度下限（`POW_LIMIT_REGTEST = 2²⁵³ − 1`，平均约 8 次哈希出一个块），其余规则完全相同。regtest 的 chain_id 不同，其区块和交易无法被其他网络接受。

### 6. 难度调整采用拆分公式

`⌊T × actual / E⌋` 按 `q × actual + ⌊r × actual / E⌋` 计算（`T = qE + r`）。这样所有中间值都能证明小于 2²⁵⁶，不必使用更宽的整数类型。Python 生成器使用未拆分的直接公式，两者结果一致即说明拆分正确。

## 后果

- 共识核心层的第三方运行时依赖只有 `sha2` 及其传递依赖。
- `deny.toml` 的许可证白名单收紧为实际使用的 MIT 和 Apache-2.0，新增许可证必须在对应 ADR 中说明。
