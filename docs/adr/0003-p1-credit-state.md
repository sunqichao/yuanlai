# ADR 0003：P1 额度状态机与存储

- 状态：已接受
- 日期：2026-09-28

## 决策

### 1. 运行时依赖 `ed25519-dalek`（BSD-3-Clause）

用于校验公钥（TX-CB-02），P2 起还用于验证交易签名。dalek 系列是 Rust 生态中审查最充分的 Ed25519 实现，并提供 `verify_strict`，可以拒绝签名延展和小阶公钥。BSD-3-Clause 与本项目的 MIT/Apache-2.0 双许可兼容，因此加入 `deny.toml` 白名单。

`curve25519-dalek` 在编译期使用过程宏，间接引入 `unicode-ident`（`(MIT OR Apache-2.0) AND Unicode-3.0`）。它只在编译时运行，不链接进任何产物；Unicode-3.0 是 OSI 认证的宽松许可证，因此一并加入白名单。

实现中发现，`VerifyingKey::from_bytes` 只做点解压，**不拒绝非规范编码**（y ≥ p）。因此 TX-CB-02 在规范中明确要求"解压后重新压缩得到相同字节"，实现和测试都覆盖了这一点。

### 2. 状态转换采用"只读校验 + 增量提交"

`validate_block` 不修改状态，而是在一个覆盖层上计算出 `BlockDelta`：

- 校验失败时状态完全不变，不需要任何回滚逻辑；
- `apply(delta)` 不会失败，`revert(delta)` 精确恢复原状态（INV-13，由测试逐块验证）；
- 同一个 `BlockDelta` 就是区块的 undo 记录，也保存了作废记录，供查询使用。

出块模板（`Chain::template`）和区块校验使用**同一套**系统交易计算代码，所以矿工和验证者对"区块应该包含什么"不可能产生分歧。

### 3. 存储采用只追加的区块文件，不使用数据库

启动时读取全部区块，并由共识层逐块**重新完整校验**，因此存储文件无需被信任，也不需要额外的状态快照格式。崩溃导致的尾部残缺记录会被识别并截断；完整但损坏的记录会报错，不会被静默丢弃。

代价：启动时间随链长线性增长。等链长到需要优化时，再引入可校验的状态快照（届时另写 ADR）。

### 4. `Chain` 目前只在链尾连接和断开区块

P1 只有单节点，不会出现分叉。在分支之间切换主链（FORK-03）需要把 `HeaderTree` 与 `Chain` 结合起来，这部分随 P5 的网络层一起实现。undo 机制本身已在 P1 完成并测试。
