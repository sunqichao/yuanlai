# 原链项目跟踪与开发计划

- 更新日期：2026-10-02
- 跟踪范围：旧版猿来协议维护状态 + 新版“文件指纹登记”产品路线
- 状态说明：**产品路线已修订为本机离线优先、联网同步可选；浏览器原型已实现本机持久化/签名/导入导出/核验及同机跨浏览器共享，单击运行版本尚未实现**；本文件只记录已验证事实和计划，不把原型写成正式凭证

## 1. 当前结论

仓库中已有可运行的旧版原型，方向是 PoW + Credit + 课程/身份交易；新版目标现明确为可下载单机应用：断网可完成文件 SHA-256、声明签名、本机保存、凭证导出与离线核验。可选共享网络只为主动同步的记录提供外部接收/确认信息，不能成为本机使用前提；旧版链历史不能默认转换为新版证明。

当前已完成产品/威胁模型工作稿、共享协议草案 0.1 和 N3 浏览器原型。原型已验证浏览器本机 Ed25519 签名、Python 回环服务将记录原子保存到同机共享 JSON 文件、旧浏览器 IndexedDB 缓存迁移、跨页面刷新、签名 JSON 导入导出及文件离线匹配核验；新增口令加密的密钥备份/恢复与旧版密钥显式轮换。仍不是单击运行应用，正式授权材料和正式离线验证器也未完成。CometBFT + Rust ABCI++ 单验证者交易/查询 PoC 通过；四验证者测试仍因 SecretConnection 认证失败而没有 peer 或共同区块。该问题保留为可选共享网络的工程风险，不再阻塞本机核心路线。SHA-256 只证明字节匹配；签名只证明密钥签署了记录；本机时间不可独立信任，产品不声称证明最早创作人或法律著作权。

## 2. 双路线状态

| 路线 | 当前状态 | 说明 |
|---|---|---|
| 旧版 P5 PoW/Credit | 继续保留，暂缓扩展 | 共识、课程登记、Credit、PoW、P2P 和 mempool 已有实现；网络仍为实验性，不能用于真实/公开存证 |
| 旧版 P6 只读 Dashboard/API | 保留为旧版管理视图 | `/` 与 `/api/overview` 可查看旧链状态；它没有文件上传、登记或证书签发功能 |
| 新版“文件指纹登记” | 本机优先路线已确认；N3 浏览器原型含同机跨浏览器共享存储和加密密钥备份/恢复 | 单击运行的离线登记仍未完成；Python 回环服务在不同浏览器间共享签名记录，网络同步仍可选且不得影响本机使用 |

### 旧版功能资产盘点

- **可作为工程基础复用**：Rust workspace 和严格 lint；确定性编码工具；SHA-256/Ed25519 实现与测试方式；append-only 存储和崩溃恢复经验；P2P 帧长度/超时/限额；HTTP 页面托管结构、Dashboard 的响应式布局经验。
- **需重做协议后才可复用**：区块存储格式、P2P 消息、RPC 数据接口。旧数据都按 PoW Block/Credit 类型编码，不能直接承载新版记录。
- **新版暂不接入**：PoW 难度与挖矿、coinbase、Credit/UTXO/转账、课程会话与旧交易池、旧 Halo2 身份流程、旧 CLI 登记命令。对应代码和文档保留并标记为 legacy，不为新版删改。
- **不能声称已具备**：新版网页上传、无币账本、验证者共识、公开验证页、证书图片/PDF、新版同步协议。

完整的 crate 复用结论和新版边界见[新版产品与技术方案](new-product-proposal.md)。N1 威胁分析见[新版威胁模型](new-threat-model.md)，N2 协议草案见[spec/v2](../spec/v2/README.md)，N3 本地界面原型见[web/v2-prototype](../web/v2-prototype/index.html)，运行步骤见[原型说明](../web/v2-prototype/README.md)。新版只读浏览器设计见[区块链浏览器设计](blockchain-explorer-design.md)，目前仅为方案，依赖共享协议、同步和最终性证明实现。旧版命令仍可在[旧版节点操作指南](node-operations.md)中查阅，该指南已标记为 legacy。

## 3. 新版开发计划

| 阶段 | 状态 | 工作项 | 完成/验收条件 |
|---|---|---|---|
| N0 产品方向 | 本机优先、可选同步已确认 | 独立运行、数据所有权、证明边界、旧版隔离 | 本机流程不依赖任何外部服务；已记录时间与作者证明限制 |
| N1 产品与威胁模型 | 工作稿待按新路线复核 | 本机密钥/备份、声明模板、时钟、隐私和可选发布威胁 | 断网创建/保存/导出/核验；共享前明确确认公开字段；不声称最早创作或自动确权 |
| N2 本机记录格式 | 原草案 0.1 需拆分；共享网络仍属候选 | 本地签名记录/备份格式与可选同步信封分离 | 先定义可离线验证的记录对象；公共网络确认不是本机记录成立条件；CometBFT 多节点 PoC 未通过且不阻塞本机 MVP |
| N3 单机产品原型 | 进行中 | 单文件 SHA-256、表单、签名、本机保存、凭证/声明模板、离线核验、本机记录浏览 | Python 回环服务将记录保存在同机共享文件，不同浏览器可查看；旧浏览器记录会在其首次打开新服务时迁移；JSON 导入导出、文件匹配和 HTTP 存储已测试；本机浏览器支持按声明内容/记录编号/指纹搜索、V1/V2 筛选、查看签名详情及跳转原文件核验；正式授权模板仍待定义 |
| N4 单机应用与数据安全 | 浏览器原型部分完成 | 本机存储、密钥管理、备份/迁移、文件边界、安装包 | 记录文件已原子持久化且服务仅监听回环；浏览器原型支持口令加密密钥备份/恢复及旧密钥显式轮换；仍需跨设备数据迁移方案、单击运行包和完整断网/重装恢复测试 |
| N5 可选共享同步 | 未开始；CometBFT P2P 有未解决问题 | 用户主动发布、公开字段确认、传输协议、远端回执、同步队列和失败恢复 | 同步关闭或失败时所有本机能力可用；共享状态与本机时间清晰区分；提交/等待确认不得冒充最终确认 |
| N6 发布与审查 | 未开始 | 跨平台打包、更新签名、隐私/法律说明、安全测试 | 单击运行、备份恢复、离线验证与可选同步都有完整验收；不宣传法律确权 |
| N7 新版区块链浏览器 | 仅有设计，未实现；依赖 N2/N5 | 只读网络总览、区块/记录精确查询、可验证证明、本地文件匹配核验 | 只查询已验证最终确认数据；显示索引高度/滞后；无链时不展示伪造数据；未同步本机记录不可查询 |

**当前优先做离线单机 MVP，不先写共识实现。** 本机记录对象、密钥/备份和离线验证先于可选共享网络协议；CometBFT 多节点问题不应阻止本机功能开发。
