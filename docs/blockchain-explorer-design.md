# 新版区块链浏览器设计

- 状态：产品/接口设计草案；不表示 V2 区块链、同步服务或浏览器已经实现
- 日期：2026-10-02
- 关联：[新版产品方案](new-product-proposal.md)、[V2 协议草案](../spec/v2/README.md)、[项目跟踪](project-tracking.md)

## 1. 目标与产品边界

浏览器是未来可选共享网络的公开只读查询入口。它让用户查到已最终确认的区块和登记记录，并检查记录签名、文件指纹及区块包含证明。它不负责创建区块，不接受登记写入，也不能替代独立验证器。

**签发不等于上链。** 当前原型在本机计算指纹、签署并保存 `local_saved` 记录，不连接 V2 账本。沿用已确认的离线优先方向，只有用户主动同步的记录才会进入共享网络；未同步的本机记录不会出现在浏览器中。网络不存在、关闭或同步失败时，本机记录和离线核验仍可用。

只有通过节点验证并带有有效最终确认凭证的记录才显示为“已确认”。`submitted`、`pending`、`rejected`、`unknown` 必须和已确认记录清楚区分，不能提前生成或展示为“已上链”。

## 2. 用户与主要任务

- 按记录 ID 或 SHA-256 指纹查找已经公开的记录。
- 按区块高度或区块 ID 查看区块、父区块和包含记录。
- 同步后从本机记录页跳转到对应交易/记录的网络确认详情。
- 检查记录签名、Merkle 包含证明和最终确认凭证。
- 选择本地原文件，在浏览器内重新计算 SHA-256；原文件不得上传给浏览器 API 或节点。

浏览器只能查询用户已发布到网络的公开数据。链上字段可能被永久复制和索引；搜索页面需明确提示，不能把“未上传文件原文”说成“元数据保密”。

## 3. 页面结构

### 网络总览

首屏显示所选网络名称/`chain_id`、当前最终确认高度、区块 ID、已索引高度、最近网络时间、验证者集合版本和数据更新时间。把“节点同步状态”和“索引状态”分开：索引落后时显示覆盖到的高度与更新时间，不把旧查询结果伪装成实时结果。没有可用网络时提供离线说明，不展示假数字。

### 区块列表与详情

区块列表按高度倒序分页，列出高度、区块 ID、父区块、网络时间、登记数量和验证者集合版本。区块详情展示规范区块头、确认状态、最终确认凭证入口及记录清单。时间标注为网络确认时间，并附上网络时钟/验证者信任边界说明。

### 记录查询与详情

查询入口支持精确匹配：记录 ID、SHA-256 指纹、区块高度、区块 ID；协议定义交易 ID 后再增加交易 ID 查询。MVP 不默认对未公开字段做全文索引。无结果时明确表示“当前索引未找到”，不得推断该作品不存在或文件从未登记。

记录详情分为：

- **网络状态**：已确认/待确认/拒绝/未知；`chain_id`、记录 ID、区块高度与 ID、区块内序号、协议版本、首次确认时间、索引更新时间。
- **签名声明**：只呈现本条已公开并经用户确认发布的字段、签名公钥和签名校验结果。V2 原型中的身份类别、声明正文是否进入链上协议，必须在 N2 冻结前明确，不能由 UI 擅自追加或推断。
- **文件指纹**：哈希算法、摘要、文件字节数。提供“选择本地文件核验”，在浏览器本地计算并仅返回匹配/不匹配结果；不发送文件内容或文件名。
- **包含与最终性证明**：Merkle 路径、区块头、验证者集合版本及共识最终确认凭证；显示本节点验证结果，并允许导出机器可读证明供独立离线验证。

页面结论应使用“记录签名有效”“文件指纹匹配”“区块包含证明有效”“网络已最终确认”等精确措辞，不使用“版权确权”“证明原创”或“最早作者”。

### 状态定义

| 状态 | 浏览器行为 |
|---|---|
| 本机保存 `local_saved` | 不进入公开浏览器；只在用户本机记录列表显示 |
| 已提交 `submitted` | 只在提交者本机同步状态中显示，不列入已确认区块 |
| 等待确认 `pending` | 可显示暂态，但明确不能作为正式链上凭证 |
| 已确认 `confirmed` | 可在区块/记录查询中公开显示，并提供验证证明 |
| 被拒绝 `rejected` | 仅向提交者解释原因；不得显示为已收录 |
| 未知 `unknown` | 显示索引高度和更新时间，说明可能未同步或不存在 |

## 4. 只读 API 草案

以下是接口建议，待 N2 协议和 N5 同步方案冻结后再确定版本、字段和分页格式。浏览器页面不得绕过节点验证，直接信任任意 peer 返回的记录。

- `GET /api/v2/network`：网络 ID、最终确认高度/区块 ID、索引高度、同步状态、验证者集合版本和更新时间。
- `GET /api/v2/blocks?cursor=...&limit=...`：有界分页的最终确认区块摘要。
- `GET /api/v2/blocks/{height_or_id}`：规范区块头、确认状态、记录 ID 列表及证明入口。
- `GET /api/v2/records/{record_id}`：公开签名记录、区块定位、记录序号、Merkle 包含证明、最终确认凭证和验证者集合标识。
- `GET /api/v2/records?fingerprint={sha256}`：同一文件指纹的全部公开登记，支持游标分页，不假设指纹全网唯一。
- `GET /api/v2/search?q=...`：可选的严格类型化精确查询；输入必须识别为允许的 ID/高度格式，不作为任意全文搜索接口。

查询响应需携带 `chain_id`、协议版本、已验证/最终确认状态、索引高度和响应生成时间。分页有上限；节点错误、不同步和索引落后必须通过状态码/字段表达，不返回看似成功的空结果。

## 5. 节点、索引与证明验证

只读 API 从已验证账本提供数据。索引是可重建的派生数据，不是共识真相：建议维护 `record_id -> block_height/record_index` 及 `fingerprint -> record_ids` 索引，并将索引检查点绑定已验证区块 ID。索引损坏或落后时，可从最后有效检查点重建；API 不可把未验证的缓存标成最终确认。

节点必须独立验证区块链接、记录签名、Merkle root 和所选 BFT 协议规定的最终确认凭证。查询 UI 还要将响应中的证明交给可复用的客户端验证模块检查；不能仅凭浏览器运营方的“绿色徽章”建立信任。客户端预置/验证 `chain_id` 和验证者集合信任根；错误网络、集合版本不匹配、缺少证明或证明失败时显示失败，不降级为普通成功。

浏览器服务与登记写入 API 分离。公开浏览器只开放只读接口；单机应用调用的 loopback API 仅绑定本机，不因添加公开浏览器而暴露本地密钥或原始文件。

## 6. 隐私与滥用控制

- 同步前逐项预览将公开字段并要求确认；确认与实际签名记录字节一致。
- 文件名默认不上链；原始文件永不通过浏览器查询 API 上传。文件选择核验只传回本机匹配结果。
- 作品名、声明人、声明正文或身份类别只有在协议允许且用户明确选择公开后才能进入共享网络；提交后按不可删除处理。V2 协议字段尚未冻结，必须先统一协议与 UI。
- 精确查询优先于全文搜索；限制分页、查询频率、响应体大小和昂贵索引条件，记录服务可观测但避免记录不必要的个人查询数据。
- 页面、API、同步进度明确区分本机时间、提交时间、最终确认时间和索引更新时间。
- 网络停机或查询失败不撤销本机记录，也不阻止本机导出、验证或另选同步时机。

## 7. 分阶段交付与验收

1. **N2 先冻结**：定稿公开记录字段、用户同步确认、`record_id`、Merkle 证明、最终确认凭证和 `chain_id`/验证者信任根；补跨实现测试向量。当前共享协议和多验证者 PoC 未达到此条件。
2. **N5 再实现节点查询**：基于经过验证的账本建立可重建索引和只读 API；覆盖分页、重复指纹、索引滞后、损坏重建、错误网络和无证明响应测试。
3. **再做浏览器 UI**：接真实 API，完成网络总览、区块列表/详情、精确记录查询/详情、本地文件匹配核验和离线证明导出；无后端时展示未连接状态，不塞入伪造链数据。
4. **跨节点验收**：两个独立节点对同一最终确认记录返回相同的规范数据与有效证明；不同步节点、错误证明、错误 `chain_id` 和篡改字段必须显式失败。
5. **隐私验收**：网络抓包证明选择原文件核验不会上传文件内容或文件名；未同步本机记录不可被公共查询发现；公开字段清单与用户确认内容一致。

区块链浏览器属于可选共享网络能力，不阻塞离线单机 MVP。现阶段可以完成产品/API 设计，但在共识、同步和最终性证明尚未冻结前，不应把浏览器伪装成已可查询的新版区块链服务。
