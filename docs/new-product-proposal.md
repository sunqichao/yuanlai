# 原链新版产品与技术方案

- 方案日期：2026-10-02
- 状态：产品方向修订为本机优先、联网同步可选（2026-10-02）；本地 Web 交互原型进行中，离线持久化、签名和可安装/单击运行版本尚未实现；公共同步协议及其治理待定
- 与旧路线关系：新建协议版本和文档；保留当前 P5 PoW/Credit 代码、规格和操作说明，不做隐式迁移或删除

## 1. 产品目标

把“猿来”做成开源、可下载、单击运行的本机文件指纹登记工具，并提供可复现构建。核心流程不依赖账号、服务器、验证者或互联网：用户选择文件，在本机计算 SHA-256，填写作品、声明人、声明身份类别和自述正文，由本机密钥签署并保存记录；随后可在本机生成指纹凭证、作品声明材料，也可离线重新核验文件、签名和凭证。

联网是可选能力。用户可以稍后主动同步一条已生成的本机记录到共享网络，获得独立的网络接收/确认信息；网络不可用、同步失败或用户不想公开时，本机登记、导出和核验仍正常工作。本机创建时间是设备记录的时间，不能单独证明它未被回拨；联网确认只能证明网络在确认时收到该记录，不能倒推离线创作时间。原始文件默认不持久保存，也不上传；用户本机保存登记元数据、签名和导出的材料。

### 用户要完成的事情

1. 下载并运行本机应用，在内置浏览器界面选择或拖入一个文件。
2. 查看文件名、大小和 SHA-256 指纹；填写作品名称、声明人及需要的创作/授权声明。
3. 本机生成并保存签名记录；导出凭证图片、PDF/打印材料或声明书。无需联网即可完成。
4. 日后在同一台或另一台设备选择原文件和凭证，离线复算摘要并验证签名；也可导入备份记录核验。
5. 如用户选择共享，再同步记录到配置的公共网络；页面分别显示“仅本机保存”“等待同步”“已获网络确认”或“同步失败”。任何同步状态都不撤销或阻断本机记录。

## 2. 证据边界与对用户的承诺

文件指纹不是“内容加密”，而是公开、确定性的哈希摘要。MVP 固定使用 SHA-256，并在协议字段中带上算法编号与版本。相同字节序列会得到相同摘要；对不同字节序列，摘要相同的概率极低，但不是数学意义上的唯一标识。微小改动、重新导出 PDF、修改文档元数据或重新压缩 ZIP 通常都会改变摘要。

本机签名记录最多支持以下结论：**持有某个本机密钥的人签署并保存过一条包含该文件指纹和声明文字的记录；重新取得完全相同字节的文件，可验证其指纹与记录一致。**本机时间来自设备时钟，容易被修改，不是独立可信时间戳。若记录后来获得网络确认，额外支持“该共享网络不晚于确认时间已收到这条记录”，不证明文件当时首次创作，也不证明用户就是最早创作者。

本机工具与可选共享网络都不能证明：

- 申报人是真实世界的著作权人，或申报内容真实；填写的权利人/作品名属于本人声明，而非程序自动核验的事实。
- 内容是原创、未抄袭，或当前用户就是最早创作人/第一个拥有该文件的人。
- 本机生成时间未被回拨，或离线记录在该时间已向第三方公开/被第三方见证。
- 文件作者、创作过程、发布时间或法律上的权利归属。
- 文件经过改写、格式转换或重新压缩后仍与原件相同。

因此产品文案应使用“本机签名的文件指纹与声明记录”“文件指纹匹配”“共享网络确认时间（如有）”，不得宣传为“自动确权”“版权认证”或“证明最早创作人”。生成的授权/声明材料是用户签署的声明模板，不替代法律审查或身份/权利核验。凭证必须清楚区分本机时间与网络确认时间，并展示此限制。

MVP 声明字段仅记录用户自述：声明人名称、声明身份类别（创作者之一/自述权利人/自述受托或授权代理人/其他）和用户填写的声明正文。签名前要求用户确认文本由本人提交；字段变化后必须重新确认。该身份类别不构成证据校验，声明正文也不是猿来向用户授予的许可，或用户对猿来的作品授权。若未来提供正式授权书或许可合同，必须另行定义许可方/被许可方、作品范围、用途、地域、期限、撤回/终止和适用法律，并经法律审查；本机原型不生成该类合同。

## 3. 证书内容与验证

建议证书字段：

| 字段 | 说明 |
|---|---|
| 品牌 | 猿来 / 原链 |
| 声明类型 | 本机签名的文件指纹与声明记录；可选网络确认不表示司法确权 |
| 作品名称 | 用户填写；以 Unicode NFC 规范化后写入规范编码 |
| 权利人/声明人 | 用户填写；是申报字段，不由链验证身份 |
| 声明身份类别 | 用户自述为创作者之一、权利人、受托/授权代理人或其他；不代表身份核验 |
| 声明正文 | 用户填写并签名；记录其本人的陈述，不自动生成第三方授权或许可 |
| 文件名与大小 | 仅作为展示元数据；文件名不参与内容摘要 |
| 摘要算法与指纹 | SHA-256 + 32 字节摘要的标准十六进制表示 |
| 本机记录时间 | 设备生成的时间；明确标注为本机时钟，不是独立可信时间戳 |
| 网络确认 | 可选字段；仅已同步时显示网络 ID、确认时间/高度和可验证回执 |
| 验证方式 | QR 码可携带记录 ID/验证地址；同时提供离线校验所需的签名记录 |
| 声明签名 | 本机密钥公钥/签名；可证明记录由对应密钥签署，不能单独证明真实姓名或著作权 |

证书图片建议采用高对比、适合打印的 PNG 版式，并提供 PDF/HTML 打印版。另可导出用户签署的作品声明/授权说明模板，文档应提示内容由用户自述。QR 码只包含记录 ID 或可选验证地址，不编码秘密信息。离线核验只依赖本地文件、导出的签名记录和受信任的验证公钥；网络回执可作为附加证据。

本机验证流程：导入/扫描记录，选择本地文件，重算 SHA-256 并检查签名。文件不离开设备。若启用共享同步，则另显示公共记录是否可查询及网络确认信息；不能将网络暂不可用显示成登记失败。

## 4. 文件与隐私规则

- 支持任意单文件字节输入，例如 ZIP、PDF、DOCX、MD；MVP 把整个文件作为一个对象哈希，不解包、不解释文件内容。
- ZIP 内多个文件的单独登记、目录清单/Merkle 根和批量上传留到后续版本。重新打包会产生不同指纹；UI 必须提示。
- 浏览器端计算哈希优先，避免上传原件。若浏览器或超大文件体验要求服务端计算，必须流式处理、限制大小/速率、临时文件隔离、失败清理，并在上传前清晰披露。
- 本机登记默认不公开。用户主动同步到共享网络时，提交确认页须逐项展示将公开的字段，并说明公开数据可能不可删除；文件名默认不随记录同步。不能把“未上传原文件”误解成元数据私密。
- 浏览器原型继续采用 50 MiB 上限，因为当前 [SubtleCrypto.digest()](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest) 路径需整块读入内存。正式版目标上限定为 1 GiB（1,073,741,824 字节），但仅在采用流式 SHA-256 后，且目标设备完成上限文件的内存、耗时、取消和失败恢复验收后启用；未满足门槛的版本不得提高原型上限。SHA-256 标准（[NIST FIPS 180-4](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf)）的输入长度边界不是设备资源建议。拒绝空文件或定义其行为；处理 Unicode 文件名、超长元数据、恶意压缩包和浏览器内存耗尽。由于不解压 ZIP，首版不受压缩炸弹影响，但仍需输入字节上限。

## 5. 本机核心与可选共享网络

本机登记是核心产品，不需要启动验证者、连接其他用户或提交公共链。正式应用须具备本机持久化、密钥创建/备份、记录导出/导入、离线签名验证和文件指纹复算。每份记录需显式标注本机时间和同步状态；同步队列与本地记录分离，网络故障不得丢弃本地数据或禁用导出/核验。

共享网络仅用于用户主动发布记录和获取附加的接收顺序/确认信息。未同步的记录只存在于用户设备或其备份，不会自动出现在其他人的安装中；跨设备/跨用户可见性需要用户配置并完成同步。共享模式不能声称证明最初创作时间或最早创作者。

### 可选共享模式：固定验证者集合的许可式共识候选

如果用户启用共享网络，无挖矿、无奖励、无币时仍需要一种抵抗女巫身份的机制来决定谁能提议和确认区块。单纯“每台电脑运行一个节点”并不能保证共识；攻击者可以运行任意多个节点。PoS 需要抵押资产，也不符合本项目目标。固定验证者曾作为共享网络候选，但不是本机核心依赖，且多验证者 PoC 尚未通过：

- 验证者公钥列表通过版本化网络配置/治理流程发布；普通用户可运行只读全节点。
- 验证者按轮次轮换提议者；区块只有取得验证者法定多数签名后才最终确认。对 `3f+1` 个验证者，提交证书至少需要 `2f+1` 个不同验证者签名。
- 普通全节点独立验证规范编码、区块链接、时间范围、记录签名、验证者签名和法定人数，然后同步最终确认区块。
- 不设置 PoW、挖矿、coinbase、手续费、Credit、转账或奖励；一次登记不会消耗代币。
- 网络信任明确来自验证者集合和其治理，而非“区块链天然可信”。验证者集合轮换、密钥泄露、超过容错数量的串谋和离线策略必须有独立规范。

这不是比特币式完全开放、无需许可的共识。具体 BFT 算法/实现、验证者名单、密钥轮换与集合治理仍待 ADR 审查；不能把简化版自研 BFT 直接宣传为已具备生产安全性。无论共享网络采用何种方案，都不得成为离线记录创建和核验的前置条件。

### 候选共享记录与浏览器

共享记录字段仍待 N2 协议冻结。作品名、权利人声明、声明正文、身份类别、文件名和文件长度都不得仅因本机记录存在就自动发布；协议需标明必需字段与可选字段，应用在每次同步前逐项展示并取得用户确认。文件名默认不上链，网络不保存文件原文。候选字段包括协议/网络版本、哈希算法 ID、文件摘要、用户选择公开的声明字段、提交公钥、客户端签名及防重放/幂等信息，最终范围须经隐私审查确定。

本机签名记录与用户确认后的共享投递对象、网络接收/确认回执应分开编码。记录签名覆盖其规范内容；网络层绑定网络 ID、协议版本和防重放字段。区块头候选字段包括父区块 ID、单调高度、协议允许范围内的 UTC 时间和本块记录 Merkle root；确认凭证须按最终选定的共识协议验证。共享网络不提供转账账户模型。

新版区块链浏览器的页面、查询 API、证明验证、索引和隐私边界见[区块链浏览器设计](blockchain-explorer-design.md)。只有带有效最终确认凭证的记录才可作为已确认查询结果；本机已保存、已提交和等待确认状态不能显示为已上链。

## 6. 软件组件与现有仓库复用评估

| 当前模块/能力 | 处理建议 | 理由 |
|---|---|---|
| `yuanlai-codec` 有界读取、确定性编码 | 可复用基础实现；为新记录定义新类型与新版本编码 | 确定性编码理念有价值，但旧类型不是新协议格式 |
| `yuanlai-crypto` SHA-256、Ed25519 | 可复用并补公开测试向量 | 新版仍需要摘要与数字签名；重审域分离和签名消息格式 |
| `yuanlai-storage` 追加式区块文件、崩溃恢复思路 | 复用存储工程经验；评估索引/快照后重做新 block schema | 当前文件保存旧 block 编码，不能直接解释新账本 |
| `yuanlai-p2p` 帧边界、超时、peer 限额、连接管理 | 可复用传输层安全约束；替换握手/消息标签/同步语义并重新审计 | 线路协议绑定旧 Network/Block/交易类型，不能原样互通 |
| `yuanlai-rpc` HTTP 监听与只读页面集成 | 可复用 HTTP 服务分层和页面托管方式；重新实现上传、签名、证书和查询 API | 当前 API 只读、无认证/TLS，不能直接承载写入或公网服务 |
| 现有 Dashboard | 仅复用布局/可访问性经验；改为文件登记、结果、验证与历史页面 | 现有页面只是只读链总览，不是用户操作台 |
| `yuanlai-consensus`、`yuanlai-miner`、`yuanlai-mempool` | 标记为旧路线，暂不接入新版 | 其共识状态和交易校验围绕 PoW、Credit、UTXO/课程会话设计 |
| `yuanlai-types` | 只参考通用新类型设计；不要复用旧 Block、Credit、Course、Tx 作为新协议 | 领域类型包含旧经济模型，强行复用会把已废弃规则带入新版 |
| `yuanlai-zk` 与旧身份承诺 | 标记为暂缓 | 新版先使用提交签名与公开声明；ZK 身份不是首版必要条件 |
| `yuanlai-cli`、`yuanlai-wasm`、`yuanlai-sim` | CLI/WASM 流程需重定；模拟器可评估复用测试模式 | 新产品主流程是 Web；具体可复用程度需在实现阶段验证 |
| spec、测试向量、旧操作手册 | 原样保留，添加 legacy 标记 | 记录旧协议决策，不能与新版协议混用 |

现有二进制区块与新版链完全分离：新版使用新的 `chain_id`、数据目录和协议版本。没有明确的跨链迁移方案前，不导入旧链记录，也不把旧 PoW 记录计为新版证明。

## 7. 新版页面规划

1. **首页/本机状态**：本机记录数、密钥/备份状态；网络连接是可选状态，不作为可用性门槛。
2. **新建记录**：选择文件、计算摘要、填写作品/声明/授权材料、预览精确内容、本机签名并保存。
3. **记录与材料**：本机时间、指纹、签名状态；生成 PNG/PDF 和可选声明/授权模板。
4. **离线验证**：导入记录/凭证、选择本地文件复算，检查签名和指纹匹配。
5. **可选同步**：用户主动发布记录，单独显示待同步、已确认或失败；失败不影响本机记录。
6. **共享网络状态（管理视图）**：仅启用同步时显示节点/peer、确认信息和同步健康度。
7. **新版公开浏览器**：单独依赖已冻结的共享协议和已验证节点查询 API；与旧版 P6 `/` Dashboard、`/api/overview` 完全区分。设计细节见[区块链浏览器设计](blockchain-explorer-design.md)。

MVP 可先交付 2、3、4 三个关键操作页；其余页面是否需要由用户测试决定。

## 8. 版本范围

### MVP 必须具备

- 可下载、单击运行的本机应用；不要求账号、互联网、验证者或公共网络。
- 本机文件选择、SHA-256 指纹、作品/声明信息、本机签名和持久保存。
- 离线生成 PNG/PDF 指纹凭证和用户声明/授权说明模板；明确标注本机时间及声明性质。
- 离线导出/导入记录、重新计算文件指纹、验证记录签名。
- 可选共享同步作为独立增强；同步失败不影响本机创建、保存、导出或验证。
- 测试覆盖断网、数据备份恢复、文件边界和错误状态；对外说明证明边界。

### 明确不做

- 挖矿、PoW、coinbase、奖励、代币、Credit、转账、手续费市场。
- 保存/分发用户上传文件，扫描文件内容或判断原创性。
- 自动核实现实身份或法律上的版权归属。
- 首版就实现目录批量上传、相似内容识别、AI 查重、匿名 ZK 身份。
- 声称数据永久可用或对任何网络分叉提供绝对时间保证。

## 9. 需要产品决策后才能冻结的事项

1. **本机密钥与备份**：密钥由应用生成还是用户导入；如何加密、备份、迁移和撤销；丢失后如何解释可验证性。
2. **声明/授权材料**：原型字段已定为声明人、身份类别和自述正文；正式法律模板、许可范围和法律审查仍未定义。签名仅证明密钥签署记录，不代表系统审查或任何一方授予许可。
3. **时间语义**：本机设备时间只作为本机记录时间；可选网络确认的时间来源、误差范围和 UI 表述。
4. **文件与隐私边界**：单文件最大字节数、ZIP 是否仅作为一个 blob 哈希、关闭应用时临时数据清理和是否允许本机保留原件。
5. **可选同步**：用户是否发布、公开哪些字段、同步目标/网络与隐私提示；离线记录如何稍后同步、备份和冲突处理。
6. **部署形态**：macOS/Windows/Linux 单击运行包、本地 Web 容器或桌面外壳；更新签名、数据迁移和恢复策略。
7. **品牌和版本**：“猿来”产品名、“原链”可选共享网络名；本机记录格式与共享协议版本分离。

## 10. 参考原则

- 先做离线优先单机应用并验证保存、签名、凭证和离线核验；只有核心稳定后才继续可选同步；界面假数据必须明确标记。
- 本机签名记录与共享网络回执分开编码、分开显示；共识/同步故障不得使本机记录不可用。
- 公共发布前完成威胁建模、协议审查、依赖审计、验证者故障演练、文件上传安全测试和可恢复备份演练。
- 旧实现始终通过独立测试维护，不为新版仓促删除；正式切换前明确旧网络只读/停止维护状态。
