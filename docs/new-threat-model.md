# 原链新版威胁模型

- 版本：草案 0.1
- 日期：2026-10-02
- 适用范围：新版单文件指纹登记、链上确认、证书签发与验证
- 状态：N1 工作稿；本机离线优先、可选共享同步已确认，共享共识/部署治理未定，不能作为安全审计结论
- 关联文档：[产品与技术方案](new-product-proposal.md)、[项目跟踪](project-tracking.md)

## 1. 安全目标与非目标

### 目标

1. 对任意受支持文件字节串，本机计算 SHA-256 的结果可跨受支持实现复现。
2. 本机登记由本机密钥签名；导出的记录可在断网状态验证签名和文件指纹。
3. 本机保存、导出、导入和核验不依赖验证者或公共网络。
4. 可选共享同步有明确的同步状态和公开字段；网络故障不能破坏或禁用本机功能。
5. 默认不保存或上传文件原文；用户能理解本机时间、网络确认时间和法律权利声明的区别。

### 非目标

- 证明自然人身份、著作权法上的权利归属、原创性、未抄袭或创作过程。
- 证明提交者是第一个创作或第一个取得该文件的人；哈希和自我声明不能证明现实中的最早创作者。
- 从哈希恢复文件、比较不同字节的语义相似度、判断文件是否“正版”。
- 在没有抗女巫资源或受信任验证者的条件下，自动产生全球唯一且不可操纵的时间顺序。
- 保证公开网络永远在线、数据永不丢失，或所有参与节点均诚实。

## 2. 资产与信任边界

| 资产/边界 | 需要保护的性质 | 当前预设 |
|---|---|---|
| 用户原始文件 | 机密性、完整性、有限生命周期 | 首选浏览器本地计算；不解包 ZIP；节点和验证者不需要文件本体 |
| 登记私钥 | 不可被窃取/冒用 | 本地生成与保管；MVP 由浏览器/本地客户端签名，不把私钥交给服务端 |
| 登记记录 | 用户可确认内容、签名可验证、数据可备份 | 默认保存在本机；只有用户主动同步时才按共享网络规则公开字段 |
| 文件摘要与声明元数据 | 一致性、可验证性，同时避免超出预期泄露 | 本机记录包含所需声明与摘要；共享数据视作可能永久公开，发布前需单独确认 |
| 验证者私钥与集合配置 | 区块确认不可伪造；集合变更可审计 | 暂定固定验证者集合；密钥硬件/轮换/撤销规则尚未设计 |
| 全节点数据目录 | 崩溃后可恢复、链状态可重建 | 规范区块重放；校验失败时停止而非静默相信缓存 |
| Web 页面/API | 来源可信、无注入、资源受限 | 只服务受控来源；公开部署前须 TLS、CSP、输入限制和安全审查 |
| 证书和二维码 | 不可误导，可回链核验 | 图片本身不是信任根；验证必须回到记录并检查区块证明 |

### 信任假设

本机模式信任本机操作系统、应用二进制和用户密钥；本机时钟可被用户或恶意软件回拨，因此本机时间不是独立时间证明。可选共享模式才引入验证者/网络信任；固定验证者 PoC 尚未通过，不能作为本机模式的前置依赖。跨设备可见性需要显式导出/导入或配置同步，不会自动发生。

## 3. 对手能力

假设攻击者可能：

- 任意创建大量节点、提交重复/伪造声明、断开或延迟网络连接。
- 修改网页、伪造证书图片、诱导用户下载恶意客户端，或利用用户误看公开字段。
- 提交畸形文件名、超大文件、截断文件、异常 Unicode 元数据或格式边界输入。
- 尝试重放签名、跨网络重放、替换作品名/声明人、利用非规范编码获得多种字节表示。
- 窃取用户私钥或验证者密钥；控制或串谋部分验证者。
- 在分区期间向不同节点展示不同链视图，或提供无法完整验证的链数据。

暂不假定攻击者能找到 SHA-256 的实际碰撞/第二原像；仍按算法可替换、摘要编码必须带算法 ID 设计，且算法淘汰需要版本升级路径。

## 4. 威胁与控制

| 威胁 | 影响 | 计划控制 | 残余风险/验证方式 |
|---|---|---|---|
| 虚报权利人或作品名 | 证书被用来冒充真实权利证明 | 字段明确称“申报人/权利人声明”；签名公钥与声明分开展示；证书写明不核实真实身份 | 仍可能被法律/社会工程误用；检查文案和用户理解度 |
| 将自述身份或代理身份误读为已核验授权 | 第三方误以为应用审查了身份、权属或代理文件 | 签名记录保存用户选择的身份类别和原文声明；签名前明确确认；任何相关字段变化都撤销确认；核验页展示被签声明 | 不验证身份、授权文件、法律效力或同意范围；正式授权材料须另行法律审查 |
| 已有作品被他人先行登记 | 公众误以为链先登记者就是真正作者 | 清楚说明只证明某密钥提交时间与文件指纹；不做“原创/确权”措辞 | 不能阻止抢先登记或裁定争议；需要法律流程而非链规则 |
| 离线记录时间被回拨或伪造 | 用户/第三方误把设备时间当作可信的最早创作时间 | 本机凭证标明时间来自设备时钟；验证页区分本机创建与可选网络接收时间；不声称证明最早创作 | 离线场景没有独立可信时间源；用户需自行保留草稿、版本历史或第三方见证等额外材料 |
| 上传文件泄露 | 商业秘密/未发布作品外泄 | 默认浏览器本地哈希；链不存原文；不上传验证文件；若服务端临时处理则最小化权限、临时隔离并可靠清理 | 浏览器扩展、恶意网页脚本或用户端恶意软件仍可读取文件；安全审查前不宣传“绝不上传” |
| 链上元数据永久暴露 | 作品名/声明人永久公开，可能泄露未发布项目或真实姓名 | 按已确认方向明文上链；提交前列出作品名、声明人、摘要、文件大小、公钥并要求明确确认；文件名默认不公开 | 不能删除；用户仍可能误填真实身份或商业机密；检查确认流程与隐私文案 |
| 恶意/超大文件耗尽资源 | 浏览器崩溃、服务端拒绝服务 | 原型上限为 500 MiB；当前 SHA-256 整块读入内存，可能造成明显内存压力；正式版目标 1 GiB 需流式 SHA-256、请求/元数据限额和失败清理，并在目标设备测峰值内存与耗时 | 500 MiB 仅为配置上限，不代表所有设备均能处理；正式版 1 GiB 尚未通过性能验收 |
| 哈希算法歧义或实现不一致 | 相同文件产生不同摘要，或算法降级 | 固定 SHA-256 标准；摘要字段包含算法 ID/版本；公开测试向量；跨 Rust/浏览器互验 | SHA-256 长期安全假设会随技术变化；升级规则须未来定义 |
| 签名被替换/重放 | 把签名搬到另一网络或替换标题/文件摘要 | 签名覆盖 chain ID、协议版本、全部规范字段、nonce；拒绝非规范编码；交易 ID 绑定完整字节 | 密钥被窃取后合法签名本身不可区分；需要密钥轮换/撤销流程 |
| 用户私钥丢失或被窃 | 无法再证明由原密钥提交，或攻击者代签 | 本地密钥生成/加密保存/备份说明；签名前展示公钥；禁止服务端托管默认密钥 | 密钥恢复通常无法在不引入托管的情况下完成；MVP 需明确不可恢复性 |
| 验证者串谋或密钥泄露 | 伪造确认时间、审查/重排登记、签冲突区块 | 明示验证者名单与法定人数；多组织独立运营；阈值签名/审计日志；密钥隔离、轮换、吊销；全节点独立验签 | 控制超过容错阈值可能破坏安全；必须给出真实运营者与治理承诺 |
| 验证者离线/网络分区 | 无法确认新记录或节点看到不同视图 | BFT 安全/活性条件写入规范；停机时宁可停止最终确认；客户端显示 pending/confirmed，不把 pending 签成证书 | 可能长时间不能登记；容错阈值与恢复协议未定 |
| 多链/重组/旧证书 | 用户看到不同节点的登记顺序或已确认记录后来消失 | 只对协议定义的最终确认签发正式证书；展示网络 ID、height、block ID、validator-set version；查询可校验证明 | 如果信任根配置被替换或验证者超阈值作恶，客户端仍会被误导 |
| 恶意证书或二维码 | 假网站要求上传文件/输入私钥 | QR 只指向公开验证记录；页面不索取私钥；证书提供离线摘要与记录定位；验证器开源 | 图片可以被复制/修改；用户必须用可信验证软件核对签名 |
| Web XSS/供应链被攻陷 | 页面窃取文件或调用密钥接口、篡改登记字段 | 内容安全策略、依赖最小化/锁定、静态资源审计、CSP、HTTPS、同源限制、签名前二次确认 | Web 客户端本身能读取文件意味着被攻陷版本可能外传；公开托管需要供应链与发布签名 |
| 垃圾登记/无费用滥用 | 验证者和节点被填满、用户无法提交 | 有界记录大小、配额/速率限制、验证者接纳策略、监控和滥用处理；避免以未说明的代币费用替代 | 许可式验证者仍可拒绝服务；若开放写入需额外抗女巫机制 |
| 节点/验证者数据丢失 | 查询和同步无法完整提供历史证据 | 多运营者独立保存；可验证快照+完整重放；备份恢复演练；监控存储损坏 | 区块链不自动保证所有参与者长期保留数据；运营者可能同时丢失 |
| 时钟操纵 | 链上 UTC 时间偏离真实时间 | 时间来自最终区块但受验证者时钟约束；规定最大前后偏差并监测；必要时引入外部时间戳锚定 | 没有外部可信时间源时只能给出协议定义的时间窗口，不是绝对可信民用时间 |

## 5. 设计要求与验收检查

在 N2 协议冻结前必须具备：

- **精确的声明语义**：UI、证书、API 和法律/隐私说明一致使用“声明登记/指纹匹配”措辞。
- **声明签名覆盖**：V2 签名覆盖身份类别与完整声明正文；编辑声明相关字段后必须重新确认；V1 记录继续按旧字段验签，并明确不包含这些声明字段。
- **签名覆盖测试**：逐字段篡改、跨网络重放、旧协议重放、重复 nonce 与编码别名均被拒绝。
- **文件边界测试**：空文件、单字节、500 MiB 原型边界、正式版目标 1 GiB 边界、超过上限、文件内容变更一位、不同实现结果一致；1 GiB 验收需记录目标设备峰值内存、耗时、取消和失败恢复。
- **不上传证明**：浏览器验证流程断网仍可计算摘要；网络检查确认验证文件不发往服务器；服务端路径明确测试清理。
- **离线优先证明**：断网时可创建、持久保存、导出并重新核验记录；模拟同步失败不得清除记录或禁用本机功能；本机时间需清晰标记为设备时间。
- **共识安全测试**：法定人数不足、重复验证者签名、冲突区块、验证者轮换、网络分区及超容错假设分别有测试/演练。
- **证书验证测试**：修改 PNG 上的姓名/时间不会改变链上记录；验证器以链记录为准并显示不匹配；测试伪造 QR 与错误 network ID。
- **隐私评审**：字段列表、保存期限、永久公开警告与删除限制由上线审查确认。

任何一项失败都应阻止对应版本进入公开测试，不得以 UI 显示“已上链”替代共识证明。

## 6. 当前无法保证的事项

- 由于固定验证者模型尚未确认，本草案不保证新版存在去中心化共识。
- 新版没有代码、共识测试或正式验证者运营者；本文件不是安全认证。
- 正式版 1 GiB 文件上限是有条件目标，尚未实现流式哈希或通过性能验收；区块时间误差、密钥轮换和正式备份恢复策略也未完成。作品名/声明人明文公开方向已确认，但完整提交确认文案仍未审查。
- SHA-256 匹配表示字节级匹配，不等于法律意义上“正版”或“作者本人作品”。
